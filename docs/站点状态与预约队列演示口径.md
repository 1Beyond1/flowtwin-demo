# 站点状态与预约队列演示口径

## 当前实现边界

FlowTwin 当前没有接入能链/充电运营商的实时站点接口。因此，站点补能位状态与预约队列由前端根据演示站点的容量、占用率和等待输入生成确定性的演示快照，再交给后端的 `port-discrete-event` 仿真计算。

这不是企业实时站点数据，也不是视觉模型推断出的真实排队人数。

## 站点状态

统一使用以下字段：

| 字段 | 含义 |
| --- | --- |
| `totalPorts` | 总补能位/枪位 |
| `idlePorts` | 物理空闲补能位 |
| `reservedPorts` | 已被预约锁定的补能位 |
| `availablePorts` | 当前可供普通用户使用的补能位，等于 `idlePorts - reservedPorts` |
| `chargingPorts` | 正在服务中的补能位 |
| `faultPorts` | 故障或不可用补能位 |

也兼容企业适配器可能使用的 `totalUnits`、`availableUnits`、`occupiedUnits`、`faultUnits` 等命名。

## 预约队列

| 字段 | 含义 |
| --- | --- |
| `waitingVehicles` / `queueVehicles` | 已到站、正在等待的车辆 |
| `reservationQueueAhead` | 尚未分配具体补能位，但预计会排在当前用户前面的预约订单 |
| `averageSessionMinutes` | 平均补能服务时长 |
| `estimatedReleaseMinutes` | 当前服务中的补能位预计释放时间 |

仿真会先安排已到站等待车辆和预约队列，再安排预测窗口内的新增到达车辆，然后根据最早释放时间得到到站等待时间，并计算 P50/P90。

`reservedPorts` 与 `reservationQueueAhead` 不表示同一件事：前者是已经锁定的资源，后者是尚未分配资源的前置预约订单，避免把预约数重复计算成排队数。

## 数据源替换边界

后续接入企业数据时，只需要替换站点输入层：

```text
企业/运营商接口或 OCPP
        ↓
站点状态适配器
        ↓
port-discrete-event 仿真
        ↓
路线排序、长途规划、运营分流
```

长途规划请求会保留端口状态、预约队列和释放时间等必要字段，不再因为压缩路线请求而退回到只使用 `occupancy/wait` 的聚合模型。

## 视觉模块边界

车牌 OCR 和车辆检测属于视觉校验链路，主要用于到离站识别、补能位占用校验和异常发现；它们不覆盖平台状态，也不直接替代预约队列计算。没有实时站点接口时，页面仍应明确显示“演示仿真”，不能把视觉或仿真结果写成企业实时经营数据。
