# 飞书多维表格 AI 接入配置

这份说明对应 FlowTwin 的“同步至飞书 AI”按钮。它不是把飞书页面嵌进 Demo，而是由 Demo 服务端把当前运营快照写入飞书多维表格，再读取同一条策略记录上的 AI 字段结果。

> 当前 Demo 的站点占用、价格、等待、分流和 ROI 仍是 `FlowTwin 演示仿真`。接入飞书不会把仿真字段自动变成企业实时数据；后续拿到脱敏交易和流量数据后，只需要替换输入适配层。

## 一、准备工作

需要在飞书管理后台准备一个自建应用和一个 Base：

1. 在当前比赛使用的飞书租户内创建自建应用，记录 `App ID` 和 `App Secret`。
2. 为应用申请读取、创建、更新多维表格记录所需的权限。权限名称以当前租户控制台显示为准，可先从多维表格相关的应用权限开始核对；参考[飞书开放平台权限列表](https://open.feishu.cn/document/server-docs/application-scope/scope-list?lang=zh-CN)。
3. 创建一个 Base，并把这个 Base 授权给该应用。仅创建应用、不把 Base 分享给应用，接口仍会返回权限错误。
4. 在 Base 中创建下面三张表。`同步记录` 是可选的，前两张表是必需的。

## 二、创建数据表

字段名需要与代码一致。字段类型可以按“文本 / 数字 / 日期时间”设置；代码只依赖字段名称，不依赖字段在表中的排列顺序。

### 1. `站点运营快照`（必需）

建立以下字段：

`运行批次`、`快照时间`、`站点ID`、`站点名称`、`城市`、`能源类型`、`站点容量`、`当前占用`、`15分钟到达`、`服务率`、`P50等待`、`P90等待`、`价格`、`优惠`、`分流率`、`ROI`、`数据来源`、`数据时点`。其中 `P50等待`/`P90等待` 是历史字段名，当前填入的是排队口径，不含补能服务时长。

容量、占用、到达、服务率、等待、价格、优惠、分流率和 ROI 建议使用数字字段；批次、名称、来源和时间字段使用文本或日期时间字段均可。为了让 AI 字段容易引用，建议先全部使用普通文本/数字字段，不要把这些字段设置成复杂的人员、链接或查找字段。

### 2. `运营策略`（必需）

建立以下普通字段：

`策略ID`、`运行批次`、`拥堵站`、`承接站`、`目标`、`优惠金额`、`预计分流`、`预计等待变化`、`预计ROI`、`策略输入`、`风险说明`、`审批状态`、`创建时间`。其中 `预计等待变化` 是排队变化，不是完整路线停靠时间变化。

`策略输入` 由服务端写入一段严格限长的精简 JSON，包含策略指标、拥堵/承接站名称、预测方法、P50/P90，以及总枪位、可用/已预约资源、已到站等待车辆和预约队列等必要的端口汇总。原始路线折线、POI 结构、完整预测序列不会写入这个 AI 字段；详细站点快照仍单独写入 `站点运营快照` 表。它复用现有字段，不要求在多维表中新增列；缺失字段必须由 AI 明确说“无记录”，不能把演示仿真解释成企业实时数据。

再建立一个 AI 字段，默认名称为 `AI策略`。如果使用了别的名称，需要在服务器配置 `FEISHU_AI_STRATEGY_FIELD`，名称必须与表中的字段完全一致。

AI 字段建议使用类似下面的提示词：

```text
你是补能网络运营分析助手。只根据当前记录中已有的字段给出建议，不补造实时数据。
请输出：
1. 当前最需要关注的拥堵站及依据；
2. 是否建议把需求引导至承接站；
3. 建议的优惠方向和适用用户；
4. 预计收益与风险；
5. 需要人工复核的边界。
如果字段为空或数据来源标记为 FlowTwin 演示仿真，请明确说明这是演示仿真，不要写成企业真实经营结论。
```

### 3. `同步记录`（可选）

建立以下字段：

`同步ID`、`运行批次`、`同步状态`、`开始时间`、`完成时间`、`写入数量`、`AI状态`、`错误信息`

这张表只用于记录同步过程。如果不配置它，快照表和策略表仍会同步，页面仍可以轮询策略表中的 AI 字段。

## 三、配置服务端

只在 VPS 的环境变量或被 Git 忽略的 `config.local.js` 中填写真实值，不要把这些值写进 `index.html`、`app.js`、`runtime-config.js` 或 GitHub：

```env
FEISHU_BASE_URL=https://open.feishu.cn
FEISHU_APP_ID=your_feishu_app_id
FEISHU_APP_SECRET=your_feishu_app_secret
FEISHU_BITABLE_APP_TOKEN=your_feishu_bitable_app_token
FEISHU_SNAPSHOT_TABLE_ID=your_snapshot_table_id
FEISHU_STRATEGY_TABLE_ID=your_strategy_table_id
FEISHU_SYNC_TABLE_ID=your_optional_sync_table_id
FEISHU_AI_STRATEGY_FIELD=AI策略
FEISHU_APPROVAL_FIELD=审批状态
```

其中 `FEISHU_BITABLE_APP_TOKEN` 是 Base 的标识，不是 App Secret；`tbl...` 形式的值是表标识。实际值不要发到聊天、截图或 README 中。

## 四、验证顺序

在 VPS 源码目录执行：

```powershell
npm run check
npm test
```

然后依次访问：

```text
GET  /api/feishu/health
POST /api/feishu/sync
GET  /api/feishu/sync/{syncId}
```

`/api/feishu/health` 只返回布尔配置状态，不会返回凭据。完成一次规划后，在 Demo 的“运营”区域点击“同步至飞书 AI”：

1. 先写入站点运营快照；
2. 再写入一条运营策略；
3. 页面轮询策略记录中的 `AI策略` 字段；
4. AI 字段有内容后，页面显示结果；
5. 未配置飞书时，按钮保留本地演示，不影响原来的运营仿真。

如果返回权限错误，先检查应用是否已经被授权访问这个 Base；如果返回字段错误，逐字核对表名无关、字段名是否一致；如果返回频控错误，等待后重试，不要在前端无限重试。飞书接口的频控说明见[开放平台频控指南](https://open.feishu.cn/document/server-docs/api-call-guide/frequency-control?lang=zh-CN)。

## 五、数据边界

- Demo 写入的 `数据来源` 默认是 `FlowTwin 演示仿真`，`数据时点`是本次同步时间。
- 不要在没有企业授权的情况下把个人数据、真实订单明细或未脱敏车牌写入 Base。
- 后续接入企业数据时，保持原字段口径和来源标记，并在方案文档中区分真实数据、仿真数据和算法推算结果。
- 飞书同步失败时，页面不会把失败伪装成“AI 已完成”；本地运营结果仍可独立查看。
