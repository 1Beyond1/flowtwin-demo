## 1. 这次检查在检查什么

这不是一次“页面有没有报错”的检查，而是把当前 Demo 和已经收到的企业反馈、命题中提到的技术方向放在一起复核：哪些已经能在演示中跑通，哪些只是仿真或原型，哪些还不能对外宣称已经完成。

当前项目的定位仍然是一个面向评委的可交互原型：用自然语言描述出行，结合高德真实地图能力和本地确定性算法，给出油/电补能与运营策略的演示结果。它还不是能链生产系统，也没有接入企业真实经营数据。

本轮代码存档点为 `1328f9a fix: isolate adaptive corridor fallbacks by energy branch`。该修复解决了混动模式切换后沿线兜底候选标志被另一能源分支污染的问题；代码、浏览器实测和材料口径均以当前工作区为准。

## 3. 对照企业反馈的判断

### 3.1 站点等待时间

这是当前最值得保留的创新展示点。代码已经不再把一个固定等待数字直接当作路线事实，而是：

1. 先根据每个站点和场景生成等待仿真输入；
2. 按车辆预计到站时间选择对应预测点；
3. 将预计等待放进路线可行性、最快/稳妥/成本目标排序；
4. 在评审模式展示计算依据和数据边界。

当前缺口是没有企业订单、枪口状态、实际服务时长和历史流量，所以不能说成“预测准确率已经达到某个百分比”。如果后续拿到脱敏字段，优先替换输入适配层，不要先改页面文案。

### 3.2 AI 的投入产出比

目前 AI 的主要价值是跨场景需求理解和多轮行动编排，而不是“AI 计算出了路线”：

- 把“我想去哪里”“中途吃饭”“换成燃油”“到站至少剩多少”等自然语言转成结构化 action；
- 在已有行程上判断是追加服务、增加途经点、修改约束，还是开启新行程；
- 对规则和仿真结果做面向用户的解释。

路线、能量安全、站点等待和 ROI 仍由可测试的规则/公式完成。这个边界虽然不如“AI 自动算一切”醒目，但更容易在评委追问时说明清楚。后续应补一个“AI 与规则对比实验”，用数据证明 AI 减少了输入结构化成本，而不是把公式结果归功于模型。

### 3.3 商家运营调控

能链是平台型业务，Demo 不能假设可以直接改变所有站点。当前只对显式标记为平台可执行的站点做优惠/承接计算；其他站点保留为导航或观察对象。

因此运营页展示的应是“平台在有限可调控站点上的策略模拟”，不是对全网商户的直接控制。真实落地还需要企业确认可调字段、券规则、适用用户、库存/容量限制和审批流程。

### 3.4 运营效果表达

页面和文档统一使用“预计分流”“场景 ROI”“仿真结果”等说法，不能把优惠金额、等待变化或 ROI 说成实际已获得收益。任何录屏都要保留数据来源和免责声明。

## 4. 还没有完成的命题方向

### 4.1 时空序列预测：未完成真实版本

当前是确定性仿真，不是用历史订单训练的时序模型。要做真实版本至少需要：站点/枪口 ID、时间桶、进出站/订单流量、服务时长、取消、价格/优惠、天气与路况等，并要有时间切分的离线验证。

### 4.2 强化学习：未完成，也不应为了名词硬加

当前是有约束的候选序列搜索和多目标排序，不是强化学习。若后续要探索，应该先用离线仿真环境验证策略，设定安全动作掩码，保证任何策略都不能违反到站安全约束，再决定是否加入。没有足够的状态—动作—奖励历史数据时，不能把启发式搜索改名为强化学习。

### 4.3 计算机视觉：仅完成展示契约

目前没有真实摄像头流、车牌识别模型、车位检测模型或支付闭环。视觉 MVP 只证明模块接口、结果校验、合成演示和无模型降级路径能工作。真实接入前还要解决授权、脱敏、车牌留存、误识别复核和支付安全。

### 4.4 生产并发：只做了应用层防护

现在有进程内限流、请求体边界和执行幂等缓存，能避免 Demo 被重复点击拖垮；但多进程部署、共享限流、队列、持久化幂等和监控仍未完成。不能把当前 Node 原生服务描述成已经通过生产并发验证。

## 5. 后续优先级

### P0：评委演示前必须收口

- 本地浏览器完整走通默认案例、全国目的地、低电量长途、燃油/混动、多轮补充、运营分析、飞书未配置降级、设置页、版本检查和视觉合成演示。
- 确认“同一路线合并”后的卡片数量、收起文案和三目标标签一致。
- 确认所有仿真字段、搜索不完整、CV 降级、飞书未配置状态都有明确边界提示。
- 保持 `npm run check`、`npm test`、`git diff --check` 全绿。

### P1：增强可信度和展示

- 加入 AI 与规则对比实验页或评审模式折叠区域；
- 将预测输入字段、置信度因素和等待变化放到统一的“查看依据”；
- 用固定种子准备一条短途、一条跨省、一条极端长途录屏路线；
- 根据企业确认的可调控字段替换运营演示输入。

### P2：有真实数据后再做

- 时序预测离线训练与时间外验证；
- 多目标策略的离线强化学习/策略优化实验；
- 真实 CV 模型和支付/车牌合规方案；
- 共享缓存、队列、外部限流和生产监控。

## 6. 结论

当前 Demo 已达到“能交互、能解释、能展示算法边界”的中期原型状态；还没有达到“企业真实数据驱动的生产系统”状态。下一阶段最划算的工作是收口演示可靠性和证据展示，而不是把尚未有数据支撑的时序预测、强化学习或真实视觉模型强行塞进页面。
