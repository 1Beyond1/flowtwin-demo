# 运营仿真与企业边界

## 1. 页面里的两个分析模块

点击“开始智能分析”后会按顺序出现两步：

1. **运行分流仿真**：后端根据站点状态、优惠、容量、排队和目标用户计算结构化结果；
2. **飞书 AI 运营解读**：将仿真快照同步到飞书多维表格，读取 AI 字段，返回自然语言说明。

飞书 AI 不负责路线规划，也不替代本地公式。它的作用是把结构化运营结果解释给人看；如果飞书未配置，第一步本地仿真仍然可以单独展示。

## 2. 当前仿真输入

单个站点可能包含：

- 站点名称、能源类型、容量、当前占用；
- 15 分钟到达量、服务率、P50/P90 排队；
- 平台优惠金额、平台券库存/窗口容量、预计分流；
- 是否为平台可执行站点、是否可承接分流；
- 数据来源、数据时点和风险说明。

这些字段目前来自演示场景或页面输入。只有标记为平台可执行/可承接的站点才会进入策略计算；非合作站点仍可用于导航或观察，不能被 Demo 表述成能链能够直接调控。

## 3. 结果口径

页面展示的是场景估算：


```text
预计分流 = 受优惠与目标用户影响的可承接需求比例
预计排队变化 = 仿真后的承接站/拥堵站排队差异
场景 ROI = 场景收益与优惠/运营成本的相对估算
```

实际代码会对优惠、价格、服务率、窗口容量和目标用户产生的变化进行计算。这里的运营指标是站点排队/需求侧仿真，不等于车主路线的完整停靠耗时；路线侧还会单独叠加补能服务和支付驶离缓冲。具体结果应以页面生成的字段为准，不在文档里固化一组容易过期的数字。

必须保留以下说明：

> 数据来源：FlowTwin 演示仿真；以上不是能链企业实时经营结论，也不代表已经发生的收益。

## 4. 飞书数据边界

飞书多维表格只承接当前演示快照和策略记录。AI 字段只能根据已写入字段作解释，不能凭空补出拥堵、ROI、审批状态或企业经营结论。字段缺失时，返回“未配置/无有效字段”，而不是生成看似专业的数字。

如果将来拿到企业脱敏数据，应先做字段映射和权限确认，再逐项替换演示输入；不要直接把整张企业表复制到公开 GitHub 或公开页面。

## 5. 生产化缺口

- 企业可调控站点白名单和券规则需要企业确认；
- 需要真实订单/流量/服务时长后才能校准等待预测；
- 需要 A/B 或准实验才能验证分流和 ROI；
- 多实例部署时，当前进程内限流和幂等缓存需要换成共享组件；
- 飞书 AI 的权限、字段可见范围和审计规则需要按比赛/企业要求收敛。
