# AI 与规则对比实验（待量化）

这份文档是后续实验的存档点。它要验证的是：大模型是否减少了用户表达需求和补充行程的成本，而不是把后端确定性算法的结果包装成“AI 算出来的”。

## 1. 实验问题

在同一批用户意图下比较三种输入处理方式：

1. 纯本地规则；
2. 规则预处理 + 主 AI + 规则证据门控（当前方案）；
3. 仅 AI 结构化输出（对照组，不作为生产方案）。

路线、能量、等待、运营公式和地图结果固定，只有“自然语言 → 结构化意图/action”这一层可变。

## 2. 固定测试集

建议先准备不少于 60 条脱敏/自拟文本，按以下类别各 10～15 条：

- 明确新行程：去上海东方明珠、去南京工业大学、去布达拉宫；
- 能源切换：纯电、燃油、混动以及手动电/油量；
- 可选约束：最晚到达时间、到达至少保留多少电；
- 多轮补充：先说目的地，再说中途吃饭/咖啡/休息；
- 修改与删除：换目的地、删掉某个服务停靠；
- 含糊输入：只说“去机场”“附近吃饭”“那里休息一下”；
- 反向输入：与当前行程完全无关的新目的地。

每条样本保存：原文、上一轮状态、预期 action、预期字段、是否需要澄清。不要保存真实车牌、真实个人位置或未授权业务数据。

## 3. 评价指标

| 指标 | 计算方式 | 目标含义 |
| --- | --- | --- |
| 目的地识别准确率 | 解析出的地点与人工标注一致的比例 | 能否正确开始一趟行程 |
| action 准确率 | 新行程/补充/修改/删除分类正确比例 | 多轮体验是否可靠 |
| 硬约束误加率 | 用户未说时间/余量却被加入约束的比例 | 防止模型替用户做决定 |
| 具体地点臆造率 | 用户只说类别却生成具体商家名称的比例 | 验证规则门控有效性 |
| 规则与 AI 路线一致率 | 同一结构化输入最终方案是否一致 | 证明 AI 不改变安全计算 |
| 解析失败可解释率 | 失败时是否给出可行动提示 | 降级体验 |
| 延迟与调用次数 | 端到端耗时、主/备模型请求数 | 成本与现场稳定性 |

不能把单次“看起来理解对了”当成准确率；至少要保留输入、结构化结果和最终 action 的逐条对照。

## 4. 实验流程

```text
固定样本 → 记录规则结果 → 记录规则+AI结果 → 记录仅AI结果
        → 统一送入同一份路线/能量/预测计算
        → 对比字段、方案、失败原因、耗时和调用次数
```

当前代码已有测试覆盖部分关键门控，评审模式也能展开本次规划中的规则证据、AI action 和最终安全校验；但还没有形成独立的、带人工标注集的准确率报告：

- `test/forecast-decision.test.mjs`：解析和预测决策的稳定性；
- `test/longtrip-regression.test.mjs`：多轮和长途回归；
- `test/cv.test.mjs`：视觉结果契约；
- `test/version-check.test.mjs`：版本检查降级边界。

这些测试不是完整的自然语言评测集，不能替代上面的人工标注实验。

## 5. 结果展示方式

评委模式可以新增一个折叠面板，展示：

- 用户原文；
- 规则抽取的证据；
- AI 返回的结构化 action；
- 被接受、被拒绝或需要澄清的字段；
- 最终送入路线规划器的结构化输入。

面板中不要展示 API Key、完整模型请求头或私密供应商配置。实验数据统一标注为“FlowTwin 自建样本/仿真”，不写成企业真实数据。
