# 模拟驾驶设计与素材口径

## 目的

模拟驾驶不是重新规划一条路线，而是在用户已经选定一个可执行方案后，把这条方案压缩成可观看的时间轴：

```text
已选高德路线
  → 沿路线移动演示车辆
  → 接近补能站
  → 演示预约
  → 到站车牌 OCR 入口
  → 排队等待
  → 加油/充电服务
  → 演示扣款
  → 驶离并继续导航
  → 到达目的地
```

地图路线、站点身份和可达性仍由原有规划链路提供；模拟驾驶只负责播放，不修改路线规划结果、站点预测结果或真实支付状态。

## 交互约定

- 路线卡片下方出现“开始模拟驾驶”，只有当前方案存在完整路线且通过可行性校验时才显示。
- 工具箱默认展开，可手动收起；模拟驾驶默认采用手动推进，“行驶至下一节点/进入下一阶段”只推进时间轴，不改变业务数据。
- 展示职责固定为“地图看移动、中央卡片看业务、工具箱看辅助控制”。进入站内阶段后，工具箱自动收起，避免遮挡中央卡片；站内主操作统一放在中央卡片底部，驶入/驶离路段再自动展开工具箱。
- 工具箱提供“自动演示”开关。关闭后不再自动播放，评委可以逐阶段查看预约、识别、排队、补能、扣款和驶离；开启后车辆以较慢速度沿路线移动，地图镜头以固定节奏跟随，不再用过短时间压缩长途路线。
- 站点停靠点不是用固定百分比硬推，而是把站点坐标投影到当前高德折线，再按投影进度生成停靠点；进入预约、识别、排队等站内阶段时，车辆标记会锁定到同一个投影点，避免提前停或越过站点。
- 1×、2×、3×只影响行驶阶段的播放速度。预约、识别、排队、补能、扣款等关键阶段自动按 1× 播放，便于评委观察。
- 纯电车辆进入补能节点前会根据 ETA 自动触发演示预约，并重新计算站点等待预测；燃油路线不显示充电预约。
- 纯电预约阶段用醒目的“提前预约已触发”卡片展示站点、预计到站时间、预约前后 P50/P90 重算结果和“无需手动操作”；预约不是一个需要用户点击的假按钮。燃油路线不显示该阶段。
- 站内阶段的主操作按业务顺序放在中央卡片：预约后继续行驶、执行本地 OCR、进入排队预测、进入补能服务、生成演示电子收据、确认离场、继续沿路线行驶。车牌 OCR 未完成时不能跳过识别；其余阶段不会再让评委去右侧工具箱寻找“下一步”。
- 站内卡片用五段流程条持续标出“提前预约 → 车牌识别 → 排队预测 → 补能服务 → 自动扣款”，排队阶段突出 P50/P90、排队车辆和空闲补能位；最后增加完成回顾卡，列出本轮实际展示过的高德路线、预约、OCR、排队预测、服务耗时和演示收据。
- 模拟驾驶期间保留原有行程面板和站点预测面板，站点侧继续显示 P50/P90、排队车辆、可用补能位、预约状态和数据来源，避免把模拟驾驶退化成单纯的地图动画。
- 到站识别阶段需要用户点击后才会实际请求本地 OCR 服务，并在场景卡片中显示结构化返回、耗时和来源；识别完成后才能继续下一阶段。当前 CV 服务返回结构化 OCR 结果，不回传画框图，因此不会伪造“标注画面”；模型未就绪或未识别时明确显示原因，并提供“使用预置样例继续”托底，但会明确标注为预置演示结果，不用样例中的车牌文字冒充识别结果。
- 退出模拟后恢复原来的地图视角、路线卡片和 AI 输入胶囊。
- 直达方案仍可播放“行驶 → 到达”，但不会凭空增加补能节点。

## 素材边界

`assets/simulation/` 下的图片是 AI 生成的场景示意，不是实时摄像头截图，也不作为 OCR 识别结果来源。模拟驾驶里的车牌识别按钮会实际请求本地视觉接口；接口不可用或未识别时必须如实显示，不读取图片里的文字硬填结果。

## 数据与实现边界

- 路线几何：真实高德路线（高德不可用时沿用现有离线演示路线）。
- 补能站名称、坐标：沿用现有 POI/演示站点。
- 排队、端口、服务时长、价格、预约和扣款：沿用现有演示仿真或已有扣款演示状态。
- 车牌 OCR：仅在用户点击识别按钮后调用本地 PaddleOCR；失败不降级为“已识别”，只能由用户明确选择预置样例继续。
- 车辆检测、车位检测、排队车辆检测：本版本不因场景图存在而虚构接入。
- 真实摄像头、真实支付、企业生产预约：不在本模拟播放中宣称已接入。
