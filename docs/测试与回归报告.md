## 2. 自动化覆盖范围

- 高德主备 Key 轮换、文件缓存、并发去重和旧缓存降级；
- AI 解析失败降级、主备模型、当前时间/当前电量不由模型臆造；
- 新行程与多轮补充 action；
- 全国地点解析和地理歧义提示；
- 等待预测、P50/P90 同源关系、天气因子、端口级离散事件模拟；
- 动态预测置信度和依据字段；
- 长途多站、6 站正常上限、12 站自适应预算、重复站点去重和搜索不完整状态；
- 最快/稳妥/最低成本与 Pareto/重复方案合并；
- 运营仿真、平台可执行站点过滤、飞书本地降级；
- CV 合成结果、上传 fallback、上游残缺成功结果校验；
- API 限流、可信代理 IP、执行幂等和版本检查降级。

## 3. 浏览器回归清单

每次改动 `app.js`、`index.html` 或服务端接口后，至少走以下路径：

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| B01 | 首次打开 | 不展示旧路线或机场目的地，显示待规划状态 |
| B02 | 默认东方明珠示例 | 一次点击完成解析和路线规划，目的地在上海，不出现邵阳/机场回退 |
| B03 | 100% 纯电短途 | 可直达时不强制充电 |
| B04 | 5% 纯电同一目的地 | 第一站按安全可达性重新选择，不沿用满电站点 |
| B05 | 燃油/混动切换 | 站点类型、单位和算法分支同步变化 |
| B06 | 布达拉宫/跨省长途 | 需要时出现多站；若搜索预算不完整，显示明确提示 |
| B07 | 三目标相同 | 合并重复路线，卡片数量和“方案”文案一致 |
| B08 | 多轮“中途想吃饭” | 追加服务，不把原行程全部推倒；无可行候选时如实说明 |
| B09 | 预测依据 | 能展开来源、方法、到站时间、P50/P90 和动态置信度原因 |
| B10 | 运营分析 | 仿真和飞书 AI 分两步显示，飞书未配置不影响本地仿真 |
| B11 | 设置页 | 评审/用户模式、语音自动规划开关、版本检查均可用 |
| B12 | 视觉页 | 合成画面可分析，结果标 synthetic/模拟，不把上传 fallback 当识别成功 |
| B13 | 小屏/宽页面 | 右侧面板不发生横向裁切；隐藏后可再次展开 |
| B14 | 语音录音 | 点击后有录音状态动画，未录音时静止；结束后按设置进入规划或输入框 |

### 本轮浏览器结果（2026-08-10，本地 4199 端口）

- **通过**：B01 首屏待规划；B02 东方明珠默认示例；B03 100% 纯电短途直达且不强制补能；B04 5% 纯电前往布达拉宫进入低电量安全规划，首段约 12.8 km，生成 11 次自适应补能，最终到达余量保持在安全下限以上；B05 燃油切换后站点变为油站、单位变为 L，混动切换后出现油电对比并按选中的能源路径生成路线；B07 三目标相同的路线合并为一张“最佳方案”；B08 多轮输入“中途想吃点东西”被识别为补充需求，并在当前约束下无安全服务候选时如实提示未加入；B09 动态置信度、预测依据和 AI/规则解析依据可展开；B10 本地运营分流仿真生成了券档位、承接站、引导量、等待变化和场景 ROI；B11 设置页、版本检查、评审/用户模式；B12 合成视觉分析；B13 1280×720 页面无横向溢出。
- **部分验证**：B06 已用布达拉宫极端长途验证 11 次补能和沿线兜底候选，尚未在本轮重新覆盖“搜索预算耗尽”的提示分支；B12 另外验证了上传图片 fallback：未配置视觉推理服务时明确显示“未执行”，不输出伪造识别结果；B10 没有点击会写入飞书的“开始智能分析”；B14 已检查未录音时按钮静止、点击后的 UI 状态路径，真实麦克风录音仍取决于浏览器权限，未在本轮授权验证。
- **服务候选边界**：候选加入失败时显示具体的绕行、时间或补能约束原因，不伪造“服务已加入”；混动切换后的沿线兜底候选也不再复用旧能源分支状态。

浏览器实测使用了本机私密配置中的高德/AI 服务，但没有读取、输出或写入任何 Key；版本检查结果为“当前为尚未发布的开发版本”，这是因为本地 commit 尚未推送 GitHub，不是版本检查失效。

## 5. 仍不能由自动化测试证明的内容

自动化测试没有证明高德配额充足、线上域名白名单正确、飞书远程写入权限正确、真实 AI/STT 供应商可用或生产并发达到某个数字。它们需要在不暴露密钥的本机/服务器环境中单独验证。真实麦克风录音也不能只靠代码测试证明，现场需要手动授予浏览器麦克风权限。
