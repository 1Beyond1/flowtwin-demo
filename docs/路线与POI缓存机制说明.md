# FlowTwin 路线与 POI 缓存机制说明

## 1. 这项能力解决什么问题

FlowTwin 的路线和沿线 POI 来自高德地图 Web Service。评委演示时，同一条路线可能被反复规划、切换策略或重新打开页面。如果每次点击都重新请求高德，会增加外部 API 消耗，也会受到网络抖动和上游限流影响。

因此，项目在服务端增加了文件级 AMap 缓存层：

```text
浏览器
  ↓
FlowTwin 本地 API
  ↓
检查 runtime/cache/amap
  ├─ 命中：直接返回已缓存的标准化结果
  └─ 未命中：请求高德 → 标准化 → 写入缓存 → 返回结果
```

这不是把地图页面静态截图下来，而是缓存已经由高德返回的结构化路线、地理编码和 POI 数据。

浏览器端另保留 **1 份 5 分钟完整方案快照**：只有起终点、路线几何、动力类型、电量/油量、安全余量、绕行、优先级、到达要求、服务停靠和五分钟出发压力快照全部一致时才复用。它解决“高德路线虽已命中缓存，但页面刷新后仍要重新做多途经点安全核验”的等待问题；任一规划条件变化都会重新计算。

## 2. 当前缓存范围与时间

当前版本面向比赛评审和本地演示，路线缓存已从 10 分钟调整为 **60 分钟**。这样同一场演示中重复点击不会频繁重新消耗高德路线额度。

| 数据类型 | 缓存内容 | 正常有效期 | 上游不可用时的旧缓存策略 |
| --- | --- | ---: | --- |
| 路线 | 起终点、策略、车型、途经点对应的驾车路线 | 60 分钟 | 最多继续使用 2 小时，并标记为旧缓存 |
| 周边 POI | 沿线或站点周边的加油、充电、服务区及服务推荐 POI | 24 小时 | 最多继续使用 7 天 |
| 地点文本检索 | 地点名称对应的 POI 结果 | 7 天 | 按调用场景保留 30 天降级窗口 |
| 地理编码 | 地点名称到经纬度的结果 | 30 天 | 最多继续使用 30 天 |
| 逆地理编码 | 经纬度对应城市/区域信息 | 7 天 | 最多继续使用 30 天 |
| 天气 | 天气接口返回的短时信息 | 10 分钟 | 最多继续使用 2 小时 |
| 浏览器完整方案 | 已完成 POI 提取和逐段安全核验的本次方案 | 5 分钟，仅保留 1 份 | 不使用过期结果，条件变化立即重算 |

路线的有效期仍然比 POI 和地理编码短，是因为路线返回的预计耗时可能受交通状态、道路临时变化和上游算法变化影响。当前项目还没有投入真实导航市场，所以 60 分钟是演示额度节约与结果新鲜度之间的折中；如果未来变成面向公众的实时导航产品，应按实时交通要求缩短路线 TTL，或把静态道路几何与动态 ETA 拆成两层缓存。

## 3. 缓存键如何保证不串数据

缓存键由请求类型和完整请求参数生成。路线请求至少区分以下字段：

- 起点坐标
- 终点坐标
- 规划策略：最快、最稳妥或最低成本
- 车型参数
- 途经点/补能站坐标
- 高德要求返回的字段

因此，同一条路线的三个策略不会互相覆盖；加入不同补能站或途经点后，也会产生不同缓存项。

缓存文件名使用缓存类型和请求参数的 SHA-256 摘要生成，不把上游请求 URL直接写入文件。缓存文件只保存标准化后的结果，不保存：

- 高德 Key
- Authorization 请求头
- AI Key
- Feishu Secret
- 原始请求中的敏感配置

缓存目录位于：

```text
C:\Users\16873\Documents\AI比赛\output\FlowTwin-Demo\runtime\cache\amap
```

该目录已加入 Git 忽略规则，并且被禁止通过静态文件路由直接下载。

浏览器完整方案只保留一份经过压缩的短期 `localStorage` 快照，不包含地图 Key、AI/飞书密钥、OCR 图片或识别结果；隐私模式或容量不足时会自动退回进程内缓存和正常重算。

## 4. 重复请求、并发请求与过期降级

### 4.1 重复请求

相同请求在有效期内会直接命中本地文件，不重新请求高德。接口返回中会带有缓存状态：

```json
{
  "source": "本地路线缓存 · 高德结果",
  "cache": {
    "state": "hit"
  }
}
```

第一次请求通常是：

```json
{
  "source": "高德 Web 服务路线规划 2.0",
  "cache": {
    "state": "miss"
  }
}
```

### 4.2 同时请求去重

如果多个页面或多个策略在同一时刻请求完全相同的路线，进程内会共用同一个进行中的请求，不会并发发起多次完全相同的高德调用。

### 4.3 过期缓存降级

缓存超过正常有效期后，系统会优先尝试向高德刷新。如果高德暂时超时、短暂 502 或网络不可用，但旧数据仍在允许的降级窗口内，系统可以继续返回旧缓存，同时明确标记：

```text
本地路线缓存 · 高德结果（上游暂不可用）
```

系统不会把降级结果伪装成最新实时路线。

## 5. 与项目其他数据的边界

缓存只改变“高德接口是否需要重复请求”，不改变数据来源和算法口径。

### 真实接口数据

- 起终点地理编码
- 道路路线和路线距离
- 路线折线
- 高德返回的 POI 名称、坐标和地址

### FlowTwin 演示/拟合数据

- 站点占用率
- 排队人数和 P50/P90 等待时间
- 补能服务时长
- 价格、优惠和运营 ROI
- 运营策略效果

这些字段仍然按照项目既定口径使用仿真数据或企业数据形成的离线需求先验，不会因为路线缓存而被表述成企业实时经营数据。

## 6. 本地验证结果

在本地 4187 服务上使用同一组起点、终点、策略、车型参数请求两次，结果为：

```text
第一次：cache.state = hit
第二次：cache.state = hit
缓存统计：hit 从 5 增加到 7，miss 保持 20
```

这说明相同路线的重复请求可以直接复用本地缓存，而不是每次重新计算高德路线。

在默认北京至上海长途场景中进一步验证了完整方案缓存：首次完成 POI 提取和多途经点安全核验耗时约 **28.9 秒**；同一浏览器刷新后、规划条件和五分钟压力快照保持一致时，完整方案恢复约 **1.1 秒**。页面会显示“完整补能方案缓存复用”；该数据是本机单次实测，不代表生产环境 SLA。

## 7. 可直接放入方案材料的表述

> 为降低重复演示和高并发访问对第三方地图服务的压力，FlowTwin 在服务端设计了文件级地图缓存层。系统以“请求类型 + 完整参数”生成隔离缓存键，对高德返回的路线、地理编码和 POI 结果进行标准化存储；相同路线在缓存有效期内直接复用，首次访问或缓存失效时才请求高德。项目当前处于比赛演示阶段，路线缓存有效期设置为 60 分钟，POI 和地理编码采用更长的有效期，并提供上游暂不可用时的旧缓存降级和明确标注。缓存文件不保存地图 Key、请求头或其他敏感配置，且不进入公开 Git 仓库。

## 8. 落地边界

当前实现适合单机 Demo、评委演示和小规模试用。若进入真实生产环境，还需要补充：

1. Redis 或其他共享缓存，以支持多实例部署；
2. 按道路事件、交通状态和区域设置更细的失效策略；
3. 缓存主动失效和人工刷新机制；
4. 缓存命中率、上游请求量、失败率和延迟的监控；
5. 生产环境的权限隔离、磁盘配额和缓存清理策略。

因此，当前应将其表述为“面向演示和小规模部署的服务端缓存机制”，不直接宣称已经完成生产级高并发地图基础设施。
